= M1 synthetic CPU matrix experiment

This measures the existing `enaction.tensor.f32.matmul` operation, version 1.0,
through `enaction-accelerator` and the optional `enaction-accelerator-native`.
It is a synthetic authoring-style buffer pipeline. No established game consumer
is evidenced in this repository; these numbers are not game performance gains.
M1 is the experiment milestone, not a claim about Apple M1 hardware.

== Reproduce

From the repository root, with Rust/Cargo, Bash, jq, sha256sum and Git:

[source,bash]
----
just bench scalar target/m1-scalar 101 3
# Explicit opt-in to the existing native crate; requires Zig 0.16.0 and nm.
ZIG=/path/to/zig just bench compare target/m1-compare 101 3
# Equivalent invocation without just:
bash scripts/bench-accelerator-m1.sh compare target/m1-compare-2 101 3
----

Use a new output directory each time. Missing tools, wrong Zig version, bad
fixture/source digests, build/test failures and execution/validation errors
fail the command. No reference fallback is substituted for a failed native run.
The portable default build and `just bench` require no Zig. No dependency was
added to any Cargo manifest or to the runtime.

The runner builds release binaries outside the measurement, runs the existing
conformance tests and benchmark tests, then executes three fresh processes per
backend by default. Backend order alternates between rounds. Each shape has ten
warmups and 101 samples by default; the sample seed is `0x4d312026 + sample`.
Each sample has a diagnostic pass with phase timers and a separate pass without
inner clock reads for total latency. Their order alternates. This is warm-cache,
single-threaded, fresh-buffer execution, not a cold-cache or sustained batch
experiment. Validation, printing, registry registration, startup and destruction
of buffers are outside the timed pipeline. Total latency ends when the caller's
destination copy is available. Timer/black_box overhead remains; particularly
small phases must not be interpreted as precise isolated instruction costs.

== Workload and measured quantities

One operation is exercised at four bounded shapes `(m,k,n)`: `(2,3,2)` (fixture
size), `(1,64,1)` (narrow), `(32,64,16)` (primary), and `(64,64,64)` (larger).
The payload capacities range from hundreds of bytes to 144 KiB. Synthetic A
starts row-major and B starts column-major, both in f64. A fixed wrapping LCG
generates signed values in `[-1000/997,1000/997]`. Conversion rounds to f32;
packing changes B to row-major. This deliberately measures one explicit host
representation; an already-row-major f32 consumer would not pay these costs.

[cols="1,3",options="header"]
|===
| Field | Scope
| `allocation_zero_init_ns` | Seven caller-owned Vec allocations and zero initialization; black_box makes the buffers observable.
| `generation_ns` | Fill both f64 source buffers using the fixed generator.
| `conversion_ns` | f64 to f32 for both inputs, preserving host order.
| `packing_ns` | B column-major to row-major; A needs no repacking.
| `planning_ns` | Existing registry selects the explicitly named backend.
| `compute_call_ns` | Existing checked operation, including validation, preflight and result pass. Native includes Rust descriptor marshalling, Zig FFI and returned evidence validation; those cannot be separately timed through the current public API. This is not a bare-kernel timer.
| `output_copy_ns` | Copy the result into a preallocated caller destination.
| `total_ns` | Independent pass from first allocation through destination copy, without inner clock reads; does not include buffer destruction.
| `profiled_total_ns` | Integrated diagnostic pass; phase sums need not equal it because clocks and bookkeeping take time.
| `payload_capacity_bytes` | Actual capacity bytes of all seven live vectors at copy completion: `12*m*k + 16*k*n + 8*m*n`. Excludes Vec headers, allocator metadata, code and validator storage.
| `process_peak_rss_kib` | Linux VmHWM sampled after all shapes, including validation and serialization. Null with explicit method on other OSes. This is not kernel scratch memory or a per-shape RSS delta.
|===

Summary percentiles use nearest-rank selection. Throughput is sample count
divided by the sum of measured total times. Semantic GFLOP/s uses `2*m*k*n`
per result, excluding the duplicate arithmetic required by failure-atomic
preflight. It describes useful mathematical work, not hardware FLOP counters.
Raw per-sample JSONL is retained, including both passes' numerical checks.

== Precision and contract

Inputs and accumulation use binary32 in the existing declared inner-loop order.
The validator computes a separate f64 sum over the quantized operands, records
maximum absolute and relative error (relative denominator floored at `1e-12`),
input-conversion error, mismatches against Rust result bits, and a little-endian
output FNV-1a checksum. FNV is a repeatability marker, not a security digest.
Result files and source manifests use SHA-256.

For these bounded, normal finite values, the experiment rejects error exceeding
`2*gamma_k*sum(abs(products)) + 1e-12`, with
`gamma_k = k*epsilon_f32/(1-k*epsilon_f32)`. The conservative factor and floor
cover rounding in the independent f64 oracle. This is an experiment validation
bound, not a new tolerance promise for the v1 operation. It does not measure
error against a game model or exact real-valued source inputs. A zero bit
mismatch on one machine does not make advisory f32 authoritative.

The contract accepts contiguous row-major rectangular shapes with checked
cardinalities, including zero extents. Native ABI v1 requires 64-bit pointers.
The benchmark CLI only admits the four fixed shapes and bounded sample counts;
tests additionally exercise zero extents and an odd rectangle. No strided,
batched, transposed-view, mixed-precision or GPU operation is claimed.
Non-finite inputs, arithmetic overflow and invalid shape/length requests remain
explicit failures. Existing kernels leave output unchanged on failure.

Planning uses `RequireNamedBackend`, advisory lane and tolerance-bounded
determinism. Tests reject authoritative selection and a missing named backend,
and verify failure atomicity. Backend evidence must match the requested backend,
operation and version. No retry occurs after execution failure. Timing never
enters simulation state. The benchmark's allocations are outside the engine's
per-step/per-frame path.

== Implementation evidence and consumer pins

The compared implementations are `enaction.cpu.scalar.reference` and
`enaction.cpu.zig.scalar`, using the existing safe Rust adapter and generated
Idris2-defined ABI. Native is built with `-OReleaseSafe -static -fPIC
-fcompiler-rt` by its existing build script. Rust uses Cargo release defaults
and the host target; environment overrides and the source/binary hashes are
recorded. Both kernels use scalar source loops. Compiler auto-vectorization
has not been established by instruction-level analysis; no SIMD, GPU,
tensor-core or hardware acceleration claim is made. No third backend is added:
this baseline does not justify another implementation or contract.

The operation and ABI both remain 1.0. Contract sources were inspected at
`e0933726fe0bb7eb6c1a740f142ee780551daaba`; the implementation PR carries the
corrected generated-source manifest as well as this experiment. Consumers
should pin the exact reviewed PR commit (recorded in the PR description), not
`main` or a floating `0.1.0` package version, and vendor the complete existing
`conformance/accelerator/v1` directory. Verify its `SHA256SUMS` and the generated
ABI `SOURCE.sha256`, then run the consumer's own adapter fixtures. The results'
`SOURCE-SHA256SUMS` records the exact contract, implementation and harness bytes
that ran, including changes made before the benchmark commit existed.

Idris2 remains normative for the cross-language ABI; no native layouts or
symbols are added. Rust core semantics and Creusot version-compatibility
obligations remain unchanged. Existing Creusot coverage is version acceptance,
not a proof of f32 matrix arithmetic, benchmark instrumentation or Zig kernels.
See the recorded results report for actual verification and toolchain limits.
