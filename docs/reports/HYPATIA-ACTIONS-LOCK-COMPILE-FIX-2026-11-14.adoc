= Patch description: Hypatia fails to compile on Elixir 1.19
:toc:

Repository:: Hypatia (`hyperpolymath`), file `lib/rules/actions_lock.ex`.
Basis:: A CI log excerpt from enaction-engine pull request 109 (job
132623970230, 2026-11-14). The Hypatia source file was not read, so the cause
and the fix below are inferred and must be confirmed against the file. This is
a description only; no change has been made to the Hypatia repository.

== Symptom

Compiling Hypatia fails under Elixir 1.19.4:

[source]
----
error: cannot invoke remote function :erlang.=:=/2 inside a match
  170 │           version in @supported_versions ->
  └─ lib/rules/actions_lock.ex:170: Hypatia.Rules.ActionsLock.consume_line/3
== Compilation error in file lib/rules/actions_lock.ex ==
----

== Cause (inferred)

Line 170 ends in `->`, so it is the head of a `case` or `fn` clause.
`version in @supported_versions` is written where a pattern belongs, and `in`
expands to comparison calls, which are not allowed in a pattern. `in` is only
allowed in guards and ordinary expressions. Elixir 1.19.4 rejects this at
compile time.

== Likely fix

Move the membership test into a guard.

[source,elixir]
----
# before (line ~170, inside consume_line/3)
version in @supported_versions ->

# after
version when version in @supported_versions ->
----

If the clause is already inside a `cond`, `in` would be legal there. In that
case the problem is elsewhere and the surrounding code needs a look.

`x when x in @module_attribute` is valid because the attribute expands to a
compile-time list, which the guard turns into comparisons.
