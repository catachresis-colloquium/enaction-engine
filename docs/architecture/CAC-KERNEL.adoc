= The CAC kernel contract

Status: **normative**

This is the authoritative statement of the shared cognition/affect/conation
kernel contract for the estate. It receives the reduction contract, data model
and profile rules that were drafted in IDApTIK's
`docs/architecture/esm-contract-and-repo-boundaries.md`, which now keeps only
the package-boundary sections it owns under its own ADR-0007.

It is deliberately small. It defines seams and invariants before any repository
is asked to implement a complete theory of mind.

Accepted by ADR-0013 (two-layer estate), ADR-0014 (two-rate architecture),
ADR-0015 (determinism), ADR-0016 (confidence types), ADR-0017 (crate admission
and extraction).

WARNING: The contract's *types and validators* exist in this repository as
`crates/enaction-contracts` (ADR-0019): versioning, the §3 data model, the §2
reduction signature as a trait, and the §6 package validator. The *reduction
itself* remains a specification with no implementation here — the working
evidence ledger is in IDApTIK, kept there by its ADR-0010 until the extraction
trigger fires. This prose stays normative; where crate and prose disagree, the
prose wins and the crate has a bug.

== 1. Scope and vocabulary

An **epistemic state** is an agent's current, provenance-bearing model of what
is known, believed, suspected or unknown about a world and about other agents.
It is not the world state itself.

A **trace** is the ordered record from which an epistemic state can be
reconstructed.

A **profile** supplies game- or scenario-specific vocabulary and policy without
changing kernel semantics.

The contract covers observations and their provenance; beliefs, hypotheses,
confidence and explicit uncertainty; nested beliefs; contradiction and
supersession; deterministic ordering and replay; and optional affective and
conative annotations.

It does not prescribe a cognitive architecture, a machine-learning model, a
planner, a renderer or a multiplayer protocol.

== 2. Normative reduction contract

An implementation MUST expose a deterministic reduction equivalent to:

[source]
----
reduce(
  prior_state: EpistemicState,
  event: EpistemicEvent,
  context: ReductionContext
) -> ReductionResult
----

where `ReductionResult` contains:

[source]
----
{
  state: EpistemicState,
  derived: [Belief | Hypothesis | Intention | AffectAnnotation],
  trace_entry: TraceEntry,
  diagnostics: [Diagnostic]
}
----

For the same contract version, prior state, event and context, the result MUST
be canonically equivalent byte for byte. Wall-clock time, process identity,
mailbox arrival order, hash-map iteration order and renderer state MUST NOT
alter the result. The full prohibition list is ADR-0015.

The reduction is event-sourced. A snapshot is an optimisation and MUST be
reconstructible or verifiable against the ordered event trace.

== 3. Minimum data model

Conceptual wire fields. Concrete Rust, Elixir, Idris2, Nickel or UMS
representations may differ, but field meaning and required invariants must
remain compatible.

[source]
----
EpistemicEvent {
  event_id: EventId,
  sequence: uint,
  tick: uint,
  observer: AgentId,
  subject: AgentId | World,
  kind: Observation | Communication | Inference | ActionOutcome | Correction,
  proposition: Proposition,
  confidence: Mass,
  provenance: Provenance,
  affect: optional AffectAnnotation,
  conation: optional ConativeAnnotation
}

Belief {
  belief_id: BeliefId,
  holder: AgentId,
  proposition: Proposition,
  status: Certain | Believed | Suspected | Rejected | Unknown,
  confidence: Mass,
  source_events: [EventId],
  valid_from: Tick,
  supersedes: optional BeliefId
}
----

=== Required invariants

. `event_id` is globally unique within a trace.
. `(tick, sequence)` gives a total order for reduction.
. Every non-derived belief has at least one provenance event.
. A contradiction is represented explicitly; it is not silently overwritten.
. Nested theory of mind is represented as a belief whose holder is another
  agent, subject to a declared depth and resource policy. Per ADR-0015, any such
  cap MUST be counted in deterministic units — inferences, unifications, stream
  nodes — never in milliseconds.
. `Unknown` is a first-class status, distinct from rejected or false.
. `Certain` means full belief mass (`belief == FULL`). It is certainty of
  commitment, not knowledge: mass certainty never reads as truth. Factive
  knowledge needs world truth, which a belief does not carry. The status was
  named `Known` before ADR-0024's change; on the wire it is `certain`, and
  `known` is refused.
. Every integer on the wire is in `0 ..= 2^53 − 1` (§6, canonical bytes).
. Confidence is typed and bounded, and an implementation must not confuse
  confidence with truth. The type is `Mass`; belief status derives from the
  belief-plausibility *interval* via a versioned profile policy, never from a
  hardcoded threshold. See ADR-0016.

== 4. The two-rate structure

Cognition is discrete and event-gated. Affect is continuous and per-tick. They
are joined only here, at the ledger, and exactly two values cross. ADR-0014 is
normative; the summary:

[source]
----
evidence (fixed-point masses)
  -> projection policy (declared, versioned)
    -> ground fact set
      -> relational solver
        -> intent read (solution count)
          -> conation (reads the read AND the retained belief interval)
----

**Crossing A, affect to cognition.** An affect token (argmax over a declared
ordered vocabulary, declared tie-break, hysteresis band), or a `Mass`-typed
modulation of *attention and priority — never of truth*. Affect buys attention,
not belief.

**Crossing B, cognition to affect.** A contradiction is the algedonic signal: a
bounded, provenance-bearing arousal spike. Ambiguity produces a smaller spike
scaling with the ambiguity. A unified reading produces nothing.

Nothing else crosses. No float crosses. An intent read never becomes a number
inside the kernel. Conative utilities never leave the conative layer; only the
argmax is published.

== 5. Profiles and extensions

The kernel owns event ordering, provenance, status transitions, contradiction
handling, snapshots and replay.

A profile may add propositions, predicates, actor roles, affect dimensions,
conative drives and transition policies. A profile MUST:

* declare the kernel and profile version it targets;
* use namespaced extension identifiers;
* provide a validator and a migration story for breaking changes;
* remain loadable without UMS being installed;
* avoid redefining kernel fields with different meanings.

The initial profiles are `idaptik/esm/v1` and `slavia/esm/v1`. They are
profiles, not separate semantics.

== 6. Validation and compatibility

Every package MUST declare its kernel version, profile identifier and version,
schema version, source provenance and content digest, supported migration
range, deterministic seed or seed policy, and its declared event and snapshot
guarantees.

Loaders MUST reject unknown incompatible major versions, invalid provenance,
duplicate event identifiers, non-monotonic ordering, unbounded nested-belief
expansion, and packages whose digest does not match their contents. A diagnostic
should identify the stable field path and the compatibility rule that failed.

=== Canonical bytes and the package digest

Canonical bytes are RFC 8785 JCS over integer-only I-JSON (ADR-0024, owner
ruling Q1 arm A). Every digest and every parity comparison uses them.

* A number with a fraction or an exponent is refused as `NonIntegerNumber`.
  The contract has no float field and no utility score.
* Every integer above `2^53 − 1` (or below its negation) is refused as
  `IntegerOutOfRange`. This covers every integer field: event and belief
  ids, ticks, sequences, `valid_from`, fixed seeds, and policy fields such
  as `max_order`. There is no decimal-string escape.
* Duplicate member names (`DuplicateKey`), lone surrogates, raw control
  characters, a byte-order mark, trailing input and every RFC 8259 grammar
  error (`MalformedJson`) are refused.

`manifest.digest` is the lowercase hex SHA-256 of the canonical bytes of the
package with the `manifest.digest` member omitted, because a digest cannot
hash itself. The bytes are those of the package's typed form: an absent
optional member is omitted, never written as `null`, and an empty `holders`
is omitted. The loader computes the digest itself and compares it. No caller
supplies a digest, so no caller can vouch for a mutated package.

The digest check and the status check cannot be skipped. A loader MUST also
reject a belief whose declared status differs from the status that the
*caller's* status policy derives from the belief's interval
(`status-agrees-with-interval`). The caller resolves that policy from the
profile. It never comes from the package, because a package that carried its
own policy could certify its own beliefs.

Conformance fixtures are the cross-repository currency, per ADR-0015: a contract
is real only when a fixture and its expected output are versioned together with
the owner and vendored by consumers against a recorded digest.

== 7. First interoperable slice

Deliberately narrow:

. `Observation`, `Communication`, `Inference` and `Correction` events.
. `Certain`, `Believed`, `Suspected`, `Rejected` and `Unknown` statuses.
. One level of nested belief, with a declared maximum depth.
. Provenance, confidence, contradiction, replay and snapshot verification.
. A small IDApTIK Ghost Lobby profile with fixtures shared with UMS.
. A transport-neutral fixture set for Rust and Elixir consumers.

Affect and conation attach as optional typed annotations in this slice. They do
not force the first kernel to settle the complete Slavia model.

== 8. Open problems

These are unsolved. They are recorded so they are not silently assumed. The full
statements live in IDApTIK's `esm-contract-and-repo-boundaries.md` §9.

* **The proposition language**, and whether a Dempster–Shafer focal set can
  contain a non-ground proposition. This is the hardest one and it blocks a
  single reduction crate. If irreconcilable, "one kernel" weakens to "one trace,
  two reasoners".
* **Frames do not compose.** DS needs a declared frame per question; a belief
  space is open-ended.
* **Theory-of-mind depth accounting.**
* **Affect's clock**, which sets the scale ceiling.
* **Whether affect is state or annotation.** This document permits only the
  latter; a continuous appraisal layer is the former.
* **What "verified" means**, and the rule that a veto must be an event.
* **The domain-to-stage correspondence**, which is 1:1 for exactly one scenario
  and may be a deep result or a frozen accident.
* **Nothing has been benchmarked.** No measurement exists for a solver query, a
  ledger combine, or a tick of affect.

== 9. The runner seam: `enaction-runner-output/1` and `enaction-validate`

A game runner hands its output to Enaction as a versioned document, through a
process. No runner links Enaction as a library. The document is an envelope
because world truth cannot travel inside an `EpistemicPackage`, which has no
field for it.

[source]
----
RunnerOutput {                       // contract "enaction-runner-output/1"
  contract: "enaction-runner-output/1",
  package: EpistemicPackage,         // §3 and §6
  world_truth: [Proposition]         // opaque atoms; a set, no duplicates
}

Policies {                           // contract "enaction-policies/1"
  contract: "enaction-policies/1",
  status: StatusPolicy,              // ADR-0016
  depth: DepthPolicy                 // { max_order }
}
----

=== Rules

* **Strict parsing.** The bytes MUST be integer-only I-JSON (§6). The
  envelope and every nested contract type reject an unknown member
  (`UnknownField`, with its path) before anything is canonicalised or
  hashed, so a digest always covers every member that was supplied. A
  missing member or a wrong type is `BadShape`.
* **The contract tag.** A `contract` other than `enaction-runner-output/1` is
  refused as `UnknownField` at `contract`.
* **The package** is validated by every §6 rule, with the digest computed by
  the validator. Its fault paths are prefixed `package.`.
* **World truth** is a set: a repeated atom is refused as
  `DuplicateTruthAtom`.
* **World truth is closed over the stated propositions.** The list holds
  every proposition that is true in the run's world, among the propositions
  that a belief or an event in the package states. A stated proposition that
  is absent from the list is false in that world. A reader therefore marks a
  held belief as divergent when its proposition is absent. The list says
  nothing about a proposition that the package does not state. A runner that
  cannot decide the truth of a proposition it states MUST NOT emit the
  envelope. The validator cannot check this rule, because it has no world; a
  runner's own tests carry it. (Clarified 2026-11-14 after the first real
  producer, the IDApTIK corridor runner, met the question.)
* **Policies come from the caller.** The status and depth policies are the
  caller's, resolved from the compiled profile, and are passed as a separate
  file. The envelope has no member for them, so a runner that tries to supply
  its own is refused as `UnknownField`.

=== The binary

[source,text]
----
enaction-validate --policies FILE [--mind-trace FILE] < runner-output.json
----

* `exit 0`: valid. Stdout is the canonical bytes of the envelope and a
  newline, then, with `--mind-trace`, the canonical bytes of the mind trace
  (§10) and a newline.
* `exit 1`: a validation fault in the input. Stdout is exactly one line: the
  canonical (RFC 8785) JSON object
  `{"faults":[{"detail":"…","path":"…","rule":"…"}]}`, with every fault in
  the order the validator reports it. `rule` and `path` are the stable rule
  name and field path; `detail` is prose. Stderr repeats each fault as a
  line `<rule>` TAB `<path>` TAB `<detail>` for a human reader. An adapter
  reads stdout only.
* `exit 2`: an invocation or operational failure: a missing or unknown
  argument, a missing, unreadable or invalid `--policies` file, a missing or
  unreadable `--mind-trace` file, or unreadable stdin. A message goes to stderr and nothing goes to stdout. An adapter can
  therefore tell a bad package from a broken call.

=== Deferred

These parts of completion-plan step 11 are not in `enaction-runner-output/1`.
Each arrives as a new contract version or a separate envelope, never as an
optional member of this one: frame declarations and qualified hypotheses,
evidence payloads (BPA), independence groups, a `policy_digest` on
`ProfileRef` with `--expect-profile`, and the `enaction-counterfactual/1`
envelope. Until frame declarations exist, the validator cannot check a truth
atom against a declared hypothesis.

== 10. The mind trace: `enaction-mind-trace/1`

ADR-0027 (Proposed) records the decision. A mind trace records, for each
agent and tick, the affect token and the
attention it buys, the conative ranking and the selected candidate, and the
bodily tells. It is a separate versioned document, outside
`enaction-runner-output/1`, so that the strict envelope gains no optional
member. A host kernel produces it in its own code and proves conformance
against the fixtures in `conformance/mind/v1/`; the mind crosses as bytes.

[source]
----
MindTrace {
  contract: "enaction-mind-trace/1",
  producer: { kernel: string, abi: string },
  profile: { id: string, version: string },
  vocabulary: {
    affect_tokens: [string],          // declared order; nonempty, unique
    candidates: [string],
    tells: [string]
  },
  ticks: [{
    tick: uint,
    agent: string,
    affect: {
      token: string,
      attention: optional uint,       // a mass, 0 ..= 10,000
      caused_by: [EventId]
    },
    conation: {
      ranking: [string],              // best first
      incumbent: string,              // the current commitment
      selected: string,
      target: optional string
    },
    tells: [string]
  }]
}
----

There is **no utility score and no float** in the document. The conative
layer publishes a ranking and a selection, never a score (ADR-0016), and the
canonical decoder refuses every non-integer number (ADR-0024). Affect has no
member on which it could assert a proposition: affect buys attention, never
belief (ADR-0014).

=== Rules

The validator reads the mind trace together with its paired runner output
(§9) and refuses it with a named rule when:

* the contract tag differs, or a member is unknown (`UnknownField`);
* an affect token, candidate (in `ranking`, `incumbent` or `selected`) or
  tell is not in the declared vocabulary (`UndeclaredTerm`);
* a vocabulary is empty or has a duplicate (`BadVocabulary`);
* ticks are not strictly increasing for one agent (`NonMonotonicTick`);
  ticks of different agents may interleave;
* a ranking is empty or has a duplicate, or `selected` is not in the ranking
  (`BadRanking`);
* `selected` is neither first in the ranking nor equal to `incumbent`
  (`UnexplainedSelection`). It is checked only when the ranking is well
  formed, so one defect yields one rule;
* `attention` is above full mass, 10,000 (`MassOutOfRange`);
* an affect token differs from the previous tick's token for that agent and
  `caused_by` is empty (`UncausedAffectChange`). An agent's first tick has
  no previous token;
* an identifier in `caused_by` is not an `event_id` in the paired runner
  output's package (`DanglingCause`);
* an integer is above 2^53 − 1 (`IntegerOutOfRange`).

A document that is not I-JSON, or not this shape, is refused by the
canonical decoder (`MalformedJson`, `DuplicateKey`, `NonIntegerNumber`,
`BadShape`). Through `enaction-validate`, mind-trace fault paths are
prefixed `mind_trace`.

=== Commitment override

A tick shows *commitment override* when `selected` equals `incumbent` and is
not first in `ranking`. The agent acted from commitment and not from the
ranking: the checkable form of "ill will that persists". It is derived from
the document by the validator (`commitment_override`); the producer does not
assert it, and the document has no member for it.

=== Fixtures

`conformance/mind/v1/` holds `accepted/the-grudge` (two commitment-override
ticks) and `accepted/the-flinch` (a `startle` tell), each with its expected
commitment-override ticks; `rejected/<RuleName>/` with one case for each
rule, each refused with exactly that rule; the paired `runner-output.json`
and `policies.json`; and `SHA256SUMS` over the sorted complete file set.
