== Still AGPL-3.0-or-later, and why

The generated ABI outputs only (the generator sources were relicensed in the
follow-up pull request, branch `claude/abi-regenerate-mpl2`):

* `src/interface/generated/abi/enaction_accelerator.{h,jl,rs,zig}`
* `src/interface/generated/abi/SYMBOLS`, `SOURCE.sha256`

They embed the header text emitted by `src/interface/Abi/Generate.idr` (now
`MPL-2.0`) and `SOURCE.sha256` pins the hashes of the generator sources, which
the follow-up changed. They must be regenerated, not hand-edited:

[source,sh]
----
guix time-machine -C build/channels.scm -- shell -m build/manifest.scm -- \
  ./scripts/generate-accelerator-abi.sh
guix time-machine -C build/channels.scm -- shell -m build/manifest.scm -- \
  ./scripts/generate-accelerator-abi.sh --check
----

That regeneration was NOT RUN where the follow-up was written (no `guix`
there), and `build/manifest.scm` has no confirmed Idris2 package yet. Until it
is run and committed, `generate-accelerator-abi.sh --check` is expected to fail.
After it passes, remove `LICENSES/AGPL-3.0-or-later.txt`, the AGPL stanza in
`.machine_readable/compliance/reuse/dep5`, and the AGPL entry in
`build/just/validate.just`.

Crate metadata: `crates/enaction-accelerator-native` textually includes
`enaction_accelerator.rs` and its build script compiles `enaction_accelerator.zig`,
so until they are regenerated its `Cargo.toml` declares
`license = "MPL-2.0 AND AGPL-3.0-or-later"` instead of inheriting the workspace
value. Return it to `license.workspace = true` when the regeneration lands. (Found
by Codex's review of this pull request.)
