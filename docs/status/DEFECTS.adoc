= Known defects

Open defects in this repository, recorded so that no status document has to be
read optimistically. Remove an entry only when its check passes.

== D1: the workspace did not build (critical, **FIXED 2026-07-27**)

Kept as a record because the failure mode is instructive: a grep-based invariant
watched the *spelling* of the members line and reported nothing useful when the
members stopped existing.

.Resolution
Members repointed at `crates/enaction-time` and `crates/enaction-cognition`;
`tests/idaptik_parity.rs` moved into `crates/enaction-time/tests/` with its
import corrected to `enaction_time`; the empty `crates/affective-time/`
directory removed; the stale `[workspace.dependencies]` entry pointing at the
deleted path repointed; citations in `ARCHITECTURE.md` and `README.adoc` fixed.

Verified: `cargo metadata` loads, `cargo test --workspace` passes 44 tests
including the 6 parity tests that were previously orphaned and running nowhere,
and `cargo fmt --all -- --check` is clean.

The two failing invariants were replaced rather than repaired, per ADR-0017:

* `workspace-crate` grepped for one exact `members` line. Replaced by
  `workspace-loads`, which runs `cargo metadata` — asserting the property
  rather than the spelling.
* `no-speculative-crates` counted directories. Replaced by `crate-admission`,
  which asserts the rule ADR-0012 actually meant.
* `rust-formatted` added. It was unreachable while the manifest was broken,
  because rustfmt could not load the workspace, so formatting drift could have
  accumulated invisibly.

The original description follows.

== D2: the parity test is not a cross-repository gate (open, by design — but say so)

`idaptik_parity.rs` defines its own `reference_lerp` inline, a copy of IDApTIK's
algorithm, and asserts bit-for-bit equality against it. It does not import,
link, fetch or check out anything from IDApTIK.

`EXPLAINME.adoc` already states this correctly: *"comparison with IDApTIK is a
review activity, not an automated cross-repo gate."* The defect is that the file
name and its location invite the opposite reading.

Under ADR-0015 the remedy is to promote its four proven behaviours — `lerp`
endpoint clamping, the one-term interior form, `commit`-then-`snap`, and the
`FixedStep` catch-up cap — into a versioned, hashed conformance fixture that
IDApTIK vendors with a recorded digest. Then the parity claim is enforced rather
than asserted.

== D3: the repository is named for a tradition it does not cite (open)

Grep across the whole tree for `varela`, `thompson`, `di paolo`, `autopoiesis`,
`sensorimotor`, `sense-making`, `enactivism`, `rosch`, `noë` and `gallagher`
returns nothing. `docs/theory/` contains a README and a `.gitkeep`.

Recorded as a defect rather than a naming preference because this repository's
own standard — `EXPLAINME.adoc`'s claim-to-evidence map, and AGENTS.md's *"no
fake checks"* — applies to ideas as well as code. See ADR-0018, which sets a
review date and pre-agrees the consequence of missing it.

== D4: agents read live world truth through the baseline (soundness hole, **FIXED on branch `marina/weevil-a1-observer`, 2026-11-14; not yet merged**)

`BeliefStore::belief` answered a perspective that had no delta by reading
`trace.latest_value` of the baseline trope. That trope is the world's ground
truth, so an agent with no observations read the world as it is *now*. The
completion plan's probe showed Sally reading 1000 and then 2000 in two runs
that differed only in an event she never observed. This broke
GAME-DESIGN-SYSTEM invariant 2 (observer noninterference), and it made every
false-belief scenario omniscient for any subject the agent had not yet
asserted about.

None of the 48 existing tests caught it. Each one read its fall-through with
the world unmoved since registration, where the live read and a sound read
agree.

.Resolution
ADR-0022 (Proposed), owner ruling Q2 arm A: the baseline is a frozen prior.
`register_baseline` freezes the trope's value at registration. A perspective
with no delta reads that prior, and only the empty perspective (the world)
reads live truth. `rebuild` takes the priors instead of recapturing them.

.Checks (each was shown to fail before the fix)
* `bash scripts/cargo-test-exact.sh enaction-trace observer_sally_anne_two_run_probe`
* `bash scripts/cargo-test-exact.sh enaction-trace observer_proptest_perturbs_outside_closure`
  (at least 1024 cases)
* `bash scripts/check-observer-mutant.sh`, which exits 0 only when
  `tests/mutants/omniscience.patch` makes both observer tests fail in a
  temporary copy

The store test that pinned the fall-through with an unmoved world was
corrected, not deleted, to move the world first. Against the mutant it now
fails too.

.Residual
Registration order is semantic. A world event already in the trace when a
subject is registered becomes part of every perspective's prior, so a host
that registers late reintroduces the leak for that event. ADR-0022 records
this. Arm B (default-Unknown with a visibility lattice) would remove it and
remains open.

== D5: the Lean proof gate passed while gating nothing (open — red by design since 2026-11-14)

`verification/proofs/lean4/MANIFEST` lists one module, the quarantined
template `ApiTypes.lean`, which still fails. A quarantined module that fails is
"expected", so `scripts/check-proofs.sh lean4` reported PASS having checked
no proof.

.Resolution of the gate
`check-proofs.sh` now FAILs any MANIFEST that gates zero modules, for any
prover. `tests/check-proofs-vacuous.sh` proves this both ways (lean4, agda,
coq) with a stub prover, because no prover is installed in the agent
container. The lean4 gate is therefore red, which is expected. It stays red
until a real Lean proof is gated (completion plan step 20). The template was
neither deleted nor quarantined further (ruling Q3).

.Still open
No Lean toolchain is provisioned, so the real lean4 leg has not been run here.
`build/just/proofs.just` (`just proof-check-lean4`) will now fail wherever it
runs. No CI workflow runs the lean4 leg today.
