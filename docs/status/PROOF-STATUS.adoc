= Proof Status — Enaction Engine
:toc:

== Classification rule

This ledger distinguishes four things that must not be conflated:

Confirmed proof:: A product-connected proposition was checked by its proof
tool against the actual source of authority.
Compiled scaffold:: A proof-assistant file compiles, but explicitly describes
itself as a template or does not connect to Enaction's implementation.
Tested correspondence:: Executable implementations agree on observed cases;
this is evidence, but not a formal proof.
Gap:: The proposition, implementation connection, toolchain or fail-closed gate
needed for a proof claim is absent or failing.

Scaffolding is never reported as proof. A passing aggregate proof runner means
its gated modules compiled and its quarantined modules failed as recorded; it
does not mean every file is a completed Enaction proof.

== Confirmed product proofs

The ABI claims below were rechecked on 2026-08-29 with Idris2 0.7.0 by running
`idris2 --typecheck abi.ipkg`. The Rust claims were checked with Creusot 0.13.0,
Why3 1.8.2+git and its pinned `nightly-2026-06-22` toolchain.

ABI-P6 is exhaustive: all seven equal-constructor cases and all 42 directed
unequal-constructor cases are checked by Idris2. Equivalently, this covers all
21 unordered pairs of different operations.

ABI-P7 quantifies over every natural-number buffer length in the abstract
pointer-presence model. A negative control admitted null data for a successor
length; Idris2 then rejected both impossible cases in the two converse
theorems. Restoring rejection returned the package typecheck to green. The
theorem establishes the normative policy, not refinement of every Zig entry
point.

ABI-P1 through ABI-P4 now cover all 33 fields across the four production
accelerator layouts. `CABICompliant` requires both `FieldsAligned` and
`FieldsInBounds`, while `StructLayout` retains the total-size alignment
witness. A negative control enlarged the final request field so it ended at
byte 64 in a 56-byte struct; Idris2 rejected the final bounds witness. Restoring
the eight-byte field returned the production package to green.

RUST-P1 is production source, not a copied model: `enaction-version` is the
crate that `enaction-accelerator` and `enaction-contracts` compile against,
and it is the only crate that depends on `creusot-std`, so Creusot proves it
as a whole and no harness chooses what the prover sees. A negative
control changed `<=` to `<` while retaining the exact postcondition; Creusot
then failed `Coma.vc_accepts` with only 3/4 obligations proved and the gate
exited 1. Restoring the implementation returned the gate to 4/4 files
(re-run 2026-11-17, Creusot 0.13.0). The claim
proves only the named predicate, not its callers or any other Rust
module.

== Tested implementation correspondence

These checks passed on 2026-08-29, but remain tests rather than proofs:

* `scripts/generate-accelerator-abi.sh --check` reproduced the committed C,
  Zig, Rust and Julia declarations, symbol inventory and source digest.
* `zig build test` passed for the pure-Zig FFI, including null/non-empty buffer
  rejection and failure-atomicity cases corresponding to ABI-P7.
* `just e2e` passed 3/3 gates with zero skips: corpus integrity, scalar Rust
  reference conformance, and Rust/Zig byte-for-byte parity across fresh
  processes.
* GitHub's exact pull-request head passed workspace Rust tests, Clippy,
  formatting and the separately built Zig-linked native adapter.

These observations support the model-to-code correspondence. They do not prove
the Rust implementation or the C/Zig/Rust/Julia toolchain end to end.

== Compiled scaffolding and disconnected proofs

The canonical `just proof-check-all` sweep now typechecks the production
`abi.ipkg` before checking every file in the generic manifests. Passing the
production package confirms only the propositions named above; the generic
manifest remains limited:

* `verification/proofs/idris2/ABI/Foreign.idr` compiles, but proves properties
  of a generic `FFIResult`; it is not connected to the production accelerator
  exports.
* `verification/proofs/agda/Properties.agda` compiles under `agda --safe`, but
  labels itself an Agda proof template and proves generic list/monotonicity
  examples.
* `verification/proofs/coq/TypeSafety.v` compiles, but labels itself a Coq proof
  template and proves soundness of an example expression language unrelated to
  Enaction.
* The unrelated generic Zig lifecycle scaffold and its passing placeholder
  integration test have been removed from `build.zig`; the Zig test target now
  exercises only the production accelerator implementation. The legacy
  `Abi.Foreign` / `Abi.Types` material remains in the Idris package and is still
  quarantined from the production accelerator proof claims. Their presence in a
  typechecked package does not establish a generic engine FFI safety claim.

== Explicit gaps

[cols="1,3,3", options="header"]
|===
| ID | Gap | Evidence required to close it

| ABI-G1
| The product buffer-nullability policy is proved by ABI-P7, but the old
  `verification/proofs/idris2/ABI/Pointers.idr` template remains quarantined
  and no formal refinement connects every Zig pointer check to the Idris rule.
| Retire or product-specialise the obsolete template, then prove the generated
  nullable-pointer representation and Zig validators refine ABI-P7. Until then,
  keep the existing Zig cases classified as tested correspondence.

| ABI-G2
| Product layout alignment and field bounds are proved by ABI-P1 through
  ABI-P4, but the generic layout/platform templates remain quarantined and the
  platform model in `Abi.Types` is still explicitly simplified. The production
  Zig FFI now rejects non-64-bit pointer targets and checks every buffer field
  offset, but that is enforcement and tested correspondence, not an Idris
  platform proof.
| Retire or product-specialise the generic templates and replace the fixed
  platform assumption with target-specific, checked size witnesses mechanically
  connected to the build target.

| ABI-G3
| Product `CABICompliant` certificates establish the declared Idris layout
  model, not that every target compiler gives the generated C/Zig/Rust/Julia
  declarations exactly that representation.
| Add target-specific compiler layout assertions or a mechanically checked
  refinement from generated declarations to the Idris model; keep current
  runtime layout tests as correspondence evidence.

| TP-G1
| Generic Idris2 core types and Lean public-API safety are quarantined.
| Repair, product-specialise, and promote them from quarantine.

| RUST-G1
| Creusot proves only the version-compatibility predicate;
  package validation callers, planner, integer kernels, floating-point kernels
  and native adapter remain unproved.
| Move a contract-bearing item into the proved leaf crate `enaction-version`,
  or into another leaf crate that Creusot can prove as a whole, only when
  Creusot can translate all of it; then state and positively control its own
  contract. Creusot 0.13 currently ICEs on the planner's trait-object surface.

| RUST-G2
| The fail-closed local Creusot gate is not yet provisioned in GitHub Actions.
| Install the exact Creusot 0.13.0 release and pinned Rust toolchain in a
  required workflow; do not call local tool installation a CI gate.

| CHAIN-G1
| Model-to-generated-code-to-Zig-to-Rust equivalence is tested, not proved.
| Add a proof-carrying or mechanically checked refinement chain; keep the
  current cross-language tests as independent evidence.

| SNIF-G1
| ADR-0021 defines a future BEAM/SNIF policy, but Enaction has no BEAM
  consumer, product-specific Idris2 wasm32 wire model, Zig guest, generated
  wasm32 declarations, host adapter or end-to-end evidence. Upstream SNIF
  logical proofs do not prove this absent integration, and the upstream
  model-to-code and Wasmtime/Wasmex trust gaps remain.
| On admission of a real BEAM consumer, prove the product wire invariants in
  Idris2, mechanically check the wasm32 declaration/Zig-validation refinement,
  state the runtime TCB, and keep crash-isolation, fuel and conformance tests in
  their empirical evidence class.

| HEX-G1
| The FFI passes the Hexadeca purity floor but has no sixteen-connector unified
  protocol surface. The 2026-08-29 consumer audit found no admissible current
  consumer: historical IDApTIK/UMS and Hypatia surfaces are stub/reference
  material, IDApTIK multiplayer belongs to the game/Burble boundary, UMS has no
  working Enaction adapter, and Groove has no Enaction peer pair.
| Admit such an adapter only for a real protocol consumer under the trigger in
  `docs/reports/HEXADECA-CONSUMER-AUDIT-2026-08-29.adoc`; do not treat an
  internal numeric ABI, purity scan or sixteen-member enum as a protocol
  connector or proof.
|===
